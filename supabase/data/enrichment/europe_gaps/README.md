# Europe: Place ID, phone and website gaps

The source is production's read-only export of 2026-10-31
(`export_europe_gaps_query.sql`). Per-country totals are in
`gap_summary_20261031.csv`.

## Method, per country

All values are fill-only: they are written only where the field is empty.

- **Place ID:** the venue's own Google record. For a restaurant that means
  the restaurant, not the hotel it sits in. For a hotel it must be a lodging
  record.
  - Under 100 m from the stored point: accepted.
  - 100–500 m: accepted only with the official domain.
  - A combined same-name hotel-restaurant listing is accepted.
  - A named restaurant inside a hotel never gets the hotel's record.
  - Google records marked permanently closed are held back.
- **Phone:** MICHELIN and Google agree, or the number is printed on the
  official site.
- **Website:** MICHELIN's link and the Google record agree on the domain, or
  the site loads and names the restaurant. Booking and social-media links
  are never used.

Evidence and the reason for every row, including each value held back, are
in `<cc>_gap_fill.csv`. The SQL is generated by `build_gap_fill_sql.py`.
Each row is guarded by code + name + country, and a Place ID already used
in the same table aborts the file.

## Location corrections (2026-11-01)

`prepared_location_corrections.sql` is prepared and not applied. Evidence is
in `location_corrections.csv`. It moves 18 stored points that were
0.5–53 km off, and fills the 12 Place IDs those moves unblock, plus Blue
Lagoon's phone and website.

A point moves only when two independent sources agree and our point is the
outlier:

- **11 rows:** MICHELIN's pin and the venue's own Google record are within
  150 m of each other. The new point is MICHELIN's pin. Examples: Auberge
  Sauvage (53 km), La Maison de Pierre, DiverXO, ABaC, Al Gatto Verde.
- **7 rows:** our point *is* MICHELIN's pin, and an OpenStreetMap geocode of
  the address sits within 100 m of the Google record and more than 500 m
  from MICHELIN. The new point is the Google record. Examples: Domaine des
  Andéols (5.4 km), Dromoland Castle, Altapura, Blue Lagoon.

Where the address sides with MICHELIN (Seaham Hall, Ballyfin, Ca' Matilde),
our point is right and Google's pin is off, so nothing changes. The other
cases (an address OSM could not find, or no clear winner) stay open under
QA-393/396.

**Tested:** a re-run is a no-op; a point is never moved once the row no
longer holds the old point; a renamed row aborts the file.
