# Applying the 2026-10-28 catalogue work to production

Everything here is on branch `claude/upbeat-ramanujan-4kedct`. Run it from a
machine with the Supabase CLI linked to production. Every prepared SQL file
is one transaction with its own checks: on any problem it aborts and changes
nothing.

```bash
git fetch origin && git checkout claude/upbeat-ramanujan-4kedct && git pull
```

## 1. Migrations

```bash
supabase migration list --linked      # remote should end at 20261015120000 (94 migrations)
supabase db push --linked             # applies 20261016120000, 20261016130000, 20261016140000
supabase migration list --linked      # local and remote must now agree
```

| Migration | What it does |
|---|---|
| `20261016120000_add_worlds_50_best_countries_and_cities` | 3 countries (EC, PA, VN) and 16 cities |
| `20261016130000_add_hotel_phone` | `hotels.phone`, exposed as the last column of `hotels_full` |
| `20261016140000_add_nl_2026_star_cities` | 5 NL cities |

If `db push` seems to hang after "Applying migration…", **do not retry**. See
CLAUDE.md: check for `hotels.phone` directly before concluding anything.

## 2. Catalogue data, in this order

```bash
cd supabase/data/enrichment
supabase db query --linked --file worlds_50_best_2025_2026/prepared_w50b_new_venues_import.sql
supabase db query --linked --file michelin_nl_stars_2026/prepared_nl_stars_2026.sql
supabase db query --linked --file worlds_50_best_2025_2026/prepared_w50b_phone_backfill.sql
supabase db query --linked --file michelin_nl_phones/prepared_nl_phone_backfill.sql
supabase db query --linked --file michelin_be_lu_phones/prepared_be_lu_phone_backfill.sql
supabase db query --linked --file place_id_backfill/prepared_place_id_backfill.sql
supabase db query --linked --file place_id_backfill/prepared_place_id_backfill_nl_stars_2026.sql
```

| File | Effect |
|---|---|
| W50B new venues | 26 restaurants, 22 hotels, 49 ranking rows, 32 award rows. The lists become 99/100/100. |
| NL stars 2026 | NL history relabelled 2026→2025, 8 losses, 2 corrections, 18 MICHELIN URLs, 9 new restaurants. The NL selection becomes exactly 1/20/98. |
| W50B phones | 69 restaurants, 82 hotels |
| NL phones | 100 restaurants |
| BE/LU phones | 117 restaurants |
| Place IDs | 73 hotels and 14 NL restaurants, plus Singita once the W50B import has run, plus Amangalla's corrected coordinates |
| Place IDs, new NL restaurants | The nine 2026 newly starred restaurants (`rest_1396`–`1404`). Aborts until the NL stars file has run. |

The order matters in only two places:

- The phone files need migration 20261016130000.
- The Place ID file's Singita step needs the W50B import to have run. If that
  step aborts, run the file again after the W50B import.

The NL stars file and the W50B import use separate code ranges, so either can
go first. The Place IDs for the nine new NL restaurants are a separate file, run
last, because those rows exist only after the NL stars file has run.

## 3. App build

Ship the build that carries `hotelFullColumns … phone` only **after**
migration `20261016130000` is applied. Otherwise every hotel query in that
build fails. Run `test/live_view_full_columns_test.dart` against production
first: it passes once the migration is in.

## 4. Afterwards

- Confirm `supabase migration list --linked` shows local and remote in
  agreement. This is a standing rule in CLAUDE.md.
- Tell the session. It then:
  - writes the Michelin_Database CHANGELOG data entries (QA-209, QA-216,
    QA-218, and the W50B and phone backfills);
  - moves the app CHANGELOG entries from "prepared" to "applied".
- Spot-check in the app:
  - an Amsterdam restaurant's Call button;
  - a hotel's Call button;
  - Azurite's detail page;
  - De Librije's award history (1993 → 2025).
